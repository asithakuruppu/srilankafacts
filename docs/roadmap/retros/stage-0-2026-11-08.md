## 4. What went wrong, and why

1. **The review loop was skipped.** The roadmap says agent → PR → Q05 → lead. In practice all commits landed on `main`. This did not break anything visible (tests and CI are green), but it means the 478-item crosswalk queue and the provisional-unit change were not independently reviewed. It also makes the “rework rate” metric impossible.
2. **Rights were investigated but not pursued.** The largest schedule risk in the plan was DCS reuse terms. The memo is good and the letter is drafted, but the letter was not sent, so Stage 1's public gate is still closed. This is the single most important finding.
3. **The catalogue promised more data than the snapshots contain.** `census-2024-gnd-tables.yaml` lists 12 topics and firewood indicators, but the snapshots hold only two workbooks: GN population by sex/age and occupied housing units. The D01 prompt repeats the 12-topic assumption. Stage 1 must either snapshot the remaining tables or narrow the flagship scope. **Fixed in this retrospective:** the dataset entry and D01 prompt now describe the two files actually held.
4. **Boundary-code drift is larger than “a few units”.** 63 DCS GN units (0.45%) could not be matched, 13 DS codes differ between DCS and COD-AB, and Kalmunai is split by DCS into two DS divisions but one in COD-AB. D-022 handles one half; the other half is still unresolved. This is a real Stage 1 constraint, not a QA footnote.
5. **No data build ran in CI.** CI tests code and validates metadata, but never builds the spine or a dataset from raw snapshots. A clean-machine `slf spine build` has not been exercised in CI. The S3 backend is also untested against a real bucket.
6. **The web is still a placeholder.** W01 was allowed to start in Stage 0 but did not. Stage 1 therefore starts with no design tokens, map shell or chart decision.
7. **Small documentation drift.** G01 reports 21 GN units in duplicate-name sets; W06 says 17 groups. The difference is units vs groups; it should be stated consistently.

## 5. What went right

- **Provenance is real.** Each raw file has a URL, retrieval time and sha256; each observation will carry a file/sheet/cell locator.
- **Nothing was silently dropped.** The crosswalk queue lists every unmatched unit with a reason and candidates; the geometry QA lists units outside their attribute parent.
- **The schema is strict.** Unknown catalogue keys fail CI; rights and CRS rules are enforced before a release.
- **The pipeline is reproducible.** Snapshots are immutable; the spine rebuilds from COD-AB; 90 tests cover the stages.
- **The geography spine is unusually well documented** for a first pass: 0 invalid geometries, 0 units outside their parent by more than 1% of area, and a contiguity graph with islands handled explicitly.

## 7. Re-estimate of Stage 1

### 7.1 What changed the estimate

- **Engineering is fast; verification and rights are slow.** The Stage 0 code was produced in one evening, but none of it was human-verified. Stage 1 must be sized to the lead's review capacity, not to agent output.
- **Only 2 of the 12 topic tables are held.** Population by sex/age and occupied housing units are enough for a credible first vertical slice. The rest need snapshots, extraction and, for PDF-only tables, D02.
- **Rights are unresolved.** A public beta cannot ship while `rights.status: unclear` and no decision-log entry permits publication.
- **Tamil names are 0% in the spine.** English and Sinhala names are ~99.5%; Tamil is absent. D-012 says trilingual names from day one and no machine transliteration. This does not block an English beta, but it blocks a “complete” place page claim.

### 7.2 Re-estimated Stage 1, split into two tracks

| Track | Scope | Duration (calendar, part-time) ❓ | Exit gate |
|---|---|---|---|
| **1A. Private preview** (can start now) | Ingest the two held workbooks at GN/DS/district/province/country; validate against the final report; build a candidate release (not publishable); spatial context; profile vectors; map shell and place/indicator pages; downloads/API; methodology; Q01/Q02/Q03 on the preview | **3–4 weeks** | The chain works end to end and every value is traceable; no public launch |
| **1B. Public beta** (blocked) | Remaining census topic tables (ethnicity, religion, housing amenities, etc.); rights clearance; human verification of key values; user testing with 10+ named people; corrections log | **5–6 weeks after 1A and after DCS replies** | DCS reuse terms settled or a recorded lead decision; Q01 passes; 10+ named users tried it; first citation or press mention |

**Total to public beta: 8–10 weeks after rights clear**, versus the original 10–14 weeks from a standing start. The reduction is real but modest: we have the spine and the pipeline, but we also now know the data gap and the verification gap.

### 7.3 Recommended Stage 1 sequence

1. **D01 (data):** ingest the two workbooks; validate national/district totals against the final report; cross-check nuuuwan; publish a QA report. *(This retrospective's companion work.)*
2. **D04 (release, preview mode):** build a deterministic candidate release with manifest, checksums, static API and downloads; mark it `publishable: false` with the rights reason.
3. **D06 (spatial context):** neighbour, parent and national comparisons; Local Moran clusters/outliers with FDR; small-number flags.
4. **A03 (profile vectors):** proposed `profile` space; PCA; similar places with exact contributions; sensitivity check.
5. **W01–W06 (web):** design tokens, persistent map shell, place pages, indicator pages, downloads/API, search. Use GeoJSON boundaries if PMTiles tooling is unavailable; record the deviation.
6. **C01 (methodology), Q01–Q03 (audits) on the preview.**
7. **Lead gate:** send DCS letter; QGIS spot-check; decide whether to publish with attribution. Only then start **1B**.

### 7.4 Decisions needed from the lead

1. **DCS rights:** send the letter now? If no reply by the end of 1A, choose (a) wait, (b) publish non-commercially with attribution and a notice, or (c) legal advice first. **Recommendation:** send now; prepare (b) as a documented fallback, not a default.
2. **Scope:** approve the 1A/1B split, or insist on all 12 topics before any preview. **Recommendation:** approve the split; a working preview is the best way to test the chain and show DCS what we would publish.
3. **Kalmunai:** commission the GN list or geometry needed to resolve DCS 5224, or leave it in review for 1B. **Recommendation:** leave it in review; do not create a second provisional unit without evidence.
4. **Tamil names:** accept an English/Sinhala beta with Tamil marked “not yet available”, or delay until a translator is engaged. **Recommendation:** accept for 1A; engage a translator before 1B.
5. **Review process:** enforce branch + PR + Q05 from Stage 1, even for agents. **Recommendation:** yes; it is the only way to measure rework and catch provenance errors.
