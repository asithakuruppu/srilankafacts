# R04: Draft an outreach letter, email or RTI request

| Stage | Workstream | Version | Last revised | Status |
|---|---|---|---|---|
| 0+ | Research / Partnerships | 1 | 2026-11-07 | active |

## When to use
To prepare a message to an institution, project or person: a licence clarification to DCS, a boundary question to the Survey Department, a bug report to Lanka Data Layer, an introduction to nuuuwan or LDF, or an RTI request. **The agent drafts; the lead sends.**

## Read first
- `AGENTS.md` (rule 9: no outward-facing actions)
- Relevant R01 dossier / R02 rights memo / audit
- `docs/vision/organisation-and-business-model.md` §6 (partnership approach)
- `docs/outreach/log.md` if it exists (avoid duplicates)

## Inputs (fill in)
```
RECIPIENT:   institution / project / person, and channel (letter, email, GitHub issue, RTI)
PURPOSE:     one sentence
ASKS:        the specific questions or requests (keep to 1–3)
OFFER:       what we give back (credit, bug evidence, shared results)
EVIDENCE:    links to findings to attach (e.g. audit section with the Ampara parent error)
LANGUAGE:    English (default); Sinhala/Tamil versions only as drafts for human translation
```

## Task
1. Draft a short, specific, courteous message: who we are (an early-stage independent project; **do not overstate size or status**), the specific asks, why, what we offer, and attribution commitments.
2. For bug reports to open-source projects: reproducible steps, evidence and the suggested fix if known. Use their issue template if present.
3. For **RTI requests**: check the current procedure and any prescribed form on the RTI Commission's official site, and cite the page. Name the specific records requested, the format preferred (machine-readable) and the period. Don't invent fees, form numbers or deadlines.
4. Save to `docs/outreach/{{YYYY-MM-DD}}-{{recipient_slug}}.md` with `Status: draft`, and add a row to `docs/outreach/log.md` (date, recipient, purpose, status, follow-up date).

## Constraints
- Never send, post or submit anything. Never use the lead's personal contact details in a draft unless the lead supplied them for this purpose.
- No flattery, no pressure, no claims of affiliation or endorsement.

## Verify (show real output)
A list of facts stated in the draft with their source (doc section or URL).

## Deliverables
The draft file and the outreach log entry.

## Done when
The lead can send it after a quick read, with every factual claim checked.

Report using the format in `AGENTS.md`.
