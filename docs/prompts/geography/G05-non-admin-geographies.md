# G05: Non-admin geographies and population denominators

| Stage | Workstream | Version | Last revised | Status |
|---|---|---|---|---|
| 2 | Geography | 2 | 2026-11-15 | active (refreshed with M03; `electoral` run done, `la` and `health` to run) |

## When to use
To add one non-nesting geography scheme (local authorities `la`, electoral districts and polling divisions `electoral`, or MOH areas `health`) and compute Census 2024 denominators for it. Run once per scheme, one PR per scheme. The `electoral` run (2026-11-15) is the worked example: `pipeline/slf/datasets/electoral_geography.py`, `slf electoral build`, [QA](../../qa/electoral-geography-ec-2024.md), [method](../../methods/denominators-electoral.md).

## Read first
- `AGENTS.md` (rules 2, 4, 5, 6, 12, 13)
- `docs/architecture/data-model.md` §3.1–§3.4 (schemes, ids, GN atoms, weights, aggregation)
- `catalog/geographies/schemes.yaml` (the scheme's levels and id prefix)
- The R01/R02 outputs for the scheme's boundary and membership sources in `docs/research/sources/` and `docs/research/rights/`. **If no source with known rights exists for a level, record that, build only what rights allow, and do not publish anything derived from unlicensed data** (as `electoral` did for PDs).
- `docs/research/geography/crosswalk-report.md` and `catalog/geographies/codes/` (G02): every external GN id joins through these files, never by name.
- The spine build (`uv run slf spine build`, giving `data/build/geography-spine/{geographies.parquet, geography_relations.parquet, geography_versions.geoparquet}`) and the Census 2024 builds (`data/build/census-2024-gnd-tables/`, `data/build/census-2024-topic-tables/`). A worktree may point at the main checkout's builds with `--spine-dir` and `--census-dir`.

## Inputs (fill in)
```
SCHEME:            la | health            (electoral: done)
UNIT_LIST:         official list of units with authority codes (dataset id; for electoral: the
                   Election Commission's register of electors by PD)
BOUNDARY_SOURCE:   dataset id with rights recorded, or "none"
MEMBERSHIP_LIST:   official list of GNs per unit (dataset id), or "none"
PUBLISHED_TOTALS:  official totals per unit to compare against (population, electors, ...), or "none"
```

## Task
1. **Units.** Snapshot the unit list (`slf.snapshot.snapshot_url`, paced; record failures, never skip silently) and parse it with internal checks (for example the register's PD figures must sum to each ED total). Compare unit counts with the official counts and with the boundary source; explain every difference.
2. **Ids and codes.** Assign ids per D-004 (`LK-LA-…`, `LK-ED-NN`, `LK-PD-NNX`, `LK-MOH-…`); use the authority's code where it is stable. Write `catalog/geographies/codes/<scheme>-<vintage>.csv` (GEO_CODE) and the hierarchy edges (`parent`) in `catalog/geographies/relations/<scheme>_<vintage>.csv`, generated by the build command, not by hand.
3. **Composition.** In order of preference:
   - if the unit is a set of whole admin units (as EDs are of districts), `composed_of` those units with weight 1; denominators are then exact sums of the admin units' census totals;
   - from MEMBERSHIP_LIST: `composed_of` GN, `method: official_list`;
   - by spatial overlay in EPSG:5235 with a licensed boundary: weights by buildings (`overlay_buildings`) if a licensed building source is documented, else by area (`overlay_area`).
   Flag GNs split across units. Data without rights stays in `data/build/<scheme>/` with "internal" in the file name, and is never committed.
4. **Checks (Verify):** unit counts; each spine GN's weight sum across the scheme (expect 1.0 for every GN); units with no GN; IoU of each unit's shape against the union of its GNs, in EPSG:5235; agreement with any independent assignment (for example nuuuwan's per-GN ids), reported as a count of disagreements.
5. **Denominators.** Population, households, occupied housing units and age groups from Census 2024, as Σ(weight × GN value), or as exact admin totals where step 3 allows. Compare with PUBLISHED_TOTALS and list the 10 largest differences. Report the GN-sum gap caused by GNs the crosswalk does not match (41 DCS GNs and Kalmunai 5224 as of 2026-11).
6. **Write** the QA report `docs/qa/<scheme>-<vintage>.md`, the method `docs/methods/denominators-<scheme>.md`, and any `Proposed` decision (for example publishing a level whose composition is modelled).

## Constraints
- Rates are recomputed from components. Never average rates.
- Denominators from overlays are `modelled_estimate`, with the information floor stated.
- Census age bands are five-year: do not claim an 18+ population; bracket it.
- For elections, keep to neutral wording (rule 12): electors and census populations measure different things; report differences without explaining them away.

## Verify (show real output)
The count table; the weight-sum distribution; the IoU distribution with the worst units named; the top 10 differences against published totals; `uv run slf catalog validate --root ../catalog`; `uv run pytest`.

## Deliverables
Generated codes and relations CSVs, the build command and its tests, the QA report, the methods note, and decision-log entries if needed.

## Done when
Any per-capita indicator for the scheme's published levels can be computed with a documented denominator, and every level that cannot is listed with the reason (rights, missing list) and the next step.

Report using the format in `AGENTS.md`.
